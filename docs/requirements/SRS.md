## 1. 引言

### 1.1 编写目的

明确"污染场地土壤生态-生产功能重构监管系统"的功能边界、数据范围、角色权限、算法要求、追溯流程与验收标准，使开发、测试、交付各方对"做什么、做到什么程度、如何验收"达成一致，并优先锁定一个可演示、可部署、可验收的**SRS系统闭环**。

### 1.2 项目背景

甲方需要把"污染场地数据 → 障碍因子诊断 → 功能重构评价 → 可持续利用评价 → 重构方案推荐 → 全流程监管追溯报告"做成系统闭环，用于支撑污染场地的生态-生产功能重构监管。本系统不是普通后台，也不是论文代码仓库，而是面向甲方验收的软件工程项目。

### 1.3 名词与缩写

| 术语 | 含义 |
|---|---|
| 障碍因子 | 制约土壤生态/生产功能的污染物、理化、肥力、物理或生物指标 |
| 长表（measurements） | 以 (场地, 采样点, 因子) 为粒度的检测值存储结构，避免污染物宽列无限扩展 |
| RF | Random Forest 随机森林模型 |
| SHAP | SHapley Additive exPlanations，模型可解释方法 |
| SSUI | 可持续利用指数（Sustainable Soil Use Index），评估修复后中长期持续利用潜力 |
| RBAC | 基于角色的访问控制 |
| SRS | Soil Remediation Supervision System，污染场地监管系统 |
| 用地类型 | 生产用地 / 生态用地 等，决定阈值规则适用 |

## 2. 总体描述

### 2.1 系统定位

一个面向政府监管与企业治理的污染场地监管系统，核心交付物是**单场地全流程监管追溯报告**，核心能力是**数据可信、诊断可解释、评价可追溯、方案有依据、流程可监管**。

### 2.2 业务域总览

系统覆盖四大业务域：数据管理、决策管理、全流程追溯、系统管理（详见第 3 章）。

### 2.3 用户角色

| 角色 | 说明 | 数据可见范围 |
|---|---|---|
| 系统管理员 | 全功能访问、用户/角色/参数/模型/技术库管理 | 全部 |
| 企业用户 | 录入本企业场地、生成方案、上传本企业流程记录 | 仅本企业 |
| 第三方机构 | 检测/评估机构，上传/查看被授权项目 | 仅授权项目 |
| 监管人员 | 政府监管，查看监管范围内场地与追溯 | 监管范围内 |

### 2.4 MVP 闭环范围

```
导入场地数据 → 数据校验 → 场地列表 → 场地详情 → 障碍因子识别
→ RF/SHAP 解释 → 功能重构可行性评价 → SSUI 可持续利用评价
→ 重构方案推荐 → 五阶段全流程追溯记录 → PDF 追溯报告生成 → 操作日志记录
```

MVP 以**单场地**跑通为目标，多场地统计、地图高级交互、LLM 辅助、技术库大规模扩展属于后续阶段。

### 2.5 约束与假设

约束：技术栈基线（React+TS+AntD+ECharts / FastAPI+SQLAlchemy+Alembic / PostgreSQL+PostGIS / Redis / MinIO / scikit-learn+SHAP / Jinja2+PDF / Docker+Nginx）未经批准不得更换；原始检测值不得修改；不得硬编码密钥；阈值/权重/参数/模型版本必须可追溯。

假设：真实样本字段以已归档 Excel 为准；知识库阈值以统一障碍因子知识库 V1.0 为准；开发周期约 6 个月，本 SRS 聚焦前两周 MVP。

## 3. 功能需求

### 3.5 PDF 追溯报告内容要求

报告必须包含：(1) 场地基本信息 (2) 数据来源说明 (3) 采样点信息 (4) 检测数据摘要 (5) 数据质量校验结果 (6) 障碍因子识别结果 (7) RF/SHAP 解释 (8) 功能重构可行性评价 (9) SSUI 可持续利用评价 (10) 推荐方案 (11) 五阶段追溯记录 (12) 附件清单 (13) 操作日志摘要 (14) 报告生成时间 (15) 报告版本号。禁止报告只有几段 AI 文字、无数据表、无结论来源、无版本号、不可重复生成。

## 4. 数据需求

### 4.1 数据来源与粒度

检测数据统一采用长表存储，粒度为 (site, sampling_point, factor)。因子覆盖五大类（依据知识库整合报告）：化学性质（8）、物理性质（11+）、环境指标（约 96，含重金属/VOCs/SVOCs/OCPs/PCBs/PAHs/PAEs 等）、肥力指标（12）、生物指标（发芽指数等）。

### 4.2 真实样本字段差异（重要约束）

三类实际样本字段不一致，导入必须依赖字段映射，不可假设统一表头：

- 云南个旧（重金属，134 个）：序号/采样点编号/经纬度/区域/深度上下限/土壤类型/pH/有机质/全氮磷钾/碱解氮/速效磷钾/Cu/Pb/Zn/Fe/Mn/As/备注（23 列）。
- 南京栖霞（有机，49 个）：含 pH/电导率/SOC/全氮磷钾/CEC/粒径(黏粉砂)/多种 VOC/SVOC 列（47 列），另有独立 VOC/SVOC 半定量列表 sheet。
- 乡村建设用地（复合，8 个）：经纬度/深度/土壤类型/pH/有机质/有机碳/全氮磷钾/有效磷/速效钾/水分/电导率/CEC/容重/Cd/TPH/粒径（33 列）。

### 4.3 训练样机数据

真实数据集.csv（1118 样本）含 StudyID/ExperimentID/污染风险等级/标签/土地利用类型 + 重金属(Cr/Hg/As/Pb/Cu/Zn/Ni/Cd) + 有机物(OCPs/PAHs/PCBs/PAEs) + 理化肥力(CEC/容重/砂粉黏/质地/pH/SOC/施肥/OC/N/P/K/EC/BS/团聚体/SWC) 等列，作为 RF/SHAP 样机训练集。随机数据集.csv（F1~F127 编号因子 + 省市/采样地类型/经纬度/风险等级/标签/用地类型）仅作字段对齐与压力测试参考，**不得当作真实甲方数据用于结论**。

### 4.4 知识库

统一障碍因子知识库 V1.0：403 条规则、122 唯一因子，字段为 unified_id/factor_id/level1_category/factor_name/application_scenario/applicable_scope/land_type_original/threshold_min/threshold_max/unit/threshold_original/standard_source/source。该表是 `factor_dictionary` 与 `threshold_rules` 的直接来源。

## 5. 非功能需求

安全性：密码哈希；密钥/数据库口令经环境变量注入，禁止入库与提交 `.env`；写操作全审计；文件下载与报告生成做权限校验。

可追溯性：阈值、标准、公式、权重、模型版本、参数、报告版本均可追溯到来源与时间。

可重复性：所有数据处理脚本可重复运行；报告可按当时数据版本重复生成。

可用性：关键页面具备加载态、空态、错误态、权限不足态、导出、刷新、返回、清晰导航；图表有标题/单位/来源。

性能（MVP 目标，待确认）：单场地详情页常规数据量下首屏 < 3s；导入 200 行内同步处理，更大批量异步。

可部署性：Docker Compose 一键起服务；提供环境变量模板与初始化/迁移脚本。
