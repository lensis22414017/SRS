# 验收标准（Acceptance Criteria）

**项目名称**：污染场地土壤生态-生产功能重构监管系统
**文档版本**：v0.1（初稿）
**编写日期**：2026-06-10
**编写人**：辛特助
**适用范围**：单场地 MVP 闭环 v0.1
**状态**：草稿，待裴总评审

> 验收原则：系统功能必须形成真实闭环，而不是按钮摆设、静态假图、假数据、假报告。每条标准必须"可演示、可复现、可追溯"。

---

## 1. MVP 闭环验收清单（15 条，全部 P0）

只有以下闭环全部真实跑通，MVP 才算完成。每条给出验收方法。

| # | 验收项 | 验收方法（演示步骤） | 通过判据 |
|---|---|---|---|
| AC-01 | 能登录 | 用演示账号登录系统 | 登录成功，密码以哈希存储，错误密码被拒 |
| AC-02 | 能导入真实场地数据 | 上传一个真实场地 Excel（建议云南个旧） | 文件被解析，非弹窗摆设；生成 import_batch |
| AC-03 | 字段映射+校验 | 完成源列→标准字段映射并校验 | 输出结构化校验报告，可下载，标出缺失/越界 |
| AC-04 | 检测数据入长表 | 查询数据库 measurements | 一污染物=一行；带 source_file/batch/单位 |
| AC-05 | 能查看场地列表 | 打开场地列表 | 显示真实入库场地，可筛选/分页 |
| AC-06 | 能进入场地详情 | 点击场地进入详情 | 展示基本信息+采样点+检测值，数据真实；"点位地图"Tab 以 Leaflet 渲染真实经纬度点位（非静态图片），点位颜色反映污染状态 |
| AC-07 | 能查看采样点与检测数据 | 在详情查看采样点检测值 | 与导入数据一致，可溯源 |
| AC-08 | 能完成数据校验 | 触发/查看校验结果 | 校验报告持久化，可重复查看 |
| AC-09 | 能输出障碍因子 Top-N | 触发障碍因子识别 | 返回 Top-N 因子+类别+方向+重要性，结果入库 |
| AC-10 | 能输出 SHAP 解释 | 查看某场地 SHAP 解释 | 全局重要性 + 至少一个绑定样本 ID 的局部解释 |
| AC-11 | 能输出功能重构可行性评价 | 触发评价（生产+生态） | 得分+等级+限制因子+权重来源+解释，入库 |
| AC-12 | 能输出 SSUI 评价 | 触发 SSUI 评价 | 指数+维度分+限制/风险因子+等级+解释，入库 |
| AC-13 | 能推荐方案 | 触发方案推荐 | 基于技术库匹配，绑定障碍因子，含推荐理由 |
| AC-14 | 能录入五阶段追溯 | 录入调查评估→后期管护五阶段 | 各阶段状态/操作人/时间/版本/附件持久化 |
| AC-15 | 能生成 PDF 追溯报告 | 一键生成单场地报告 | 含 15 项内容、版本号、数据快照，可重复生成 |
| AC-16 | 能记录操作日志 | 执行写操作后查日志 | 登录/导入/导出/生成报告等被审计 |
| AC-17 | 权限差异生效 | 用不同角色账号登录对比 | 企业用户只见本企业数据，前后端双重拦截 |

> 注：甲方核心闭环为 15 条；AC-16/AC-17 为系统管理必备项，纳入 MVP 验收。

## 2. 分模块详细验收

### 2.1 数据管理

通过判据：导入支持真实异构表头（三类样本字段不同，必须靠映射）；校验覆盖必填/类型/单位/阈值范围/缺失；导出内容与库一致并记日志；图表有标题/单位/数据来源 + 加载/空/错态；地图点位用真实经纬度（若 MVP 纳入地图）。
不通过：导入只弹窗不解析；校验只看类型不看阈值；图表静态假数据。

### 2.2 决策管理

通过判据：诊断结果含模型版本、数据版本、特征清单、指标；SHAP 局部解释绑定样本 ID 且可追溯到检测值；重构评价区分生产/生态指标体系，权重不写死、阈值有标准来源；SSUI 有参数来源、数据版本、等级边界；推荐绑定障碍因子且有禁用条件与理由。
不通过：只输出"重金属污染严重"泛化结论；只输出一个分数无解释；权重硬编码；LLM 直接编方案。

### 2.3 全流程追溯

通过判据：五阶段均可录入并持久化；每阶段字段齐全（状态/材料/操作人/时间/审批意见/版本/来源/是否完成/退回/进入下一阶段）；附件可上传下载且权限校验；报告记录生成时数据版本，可重复生成。
不通过：阶段是静态展示；附件按钮无后端；报告无版本号或不可重生成。

### 2.4 系统管理

通过判据：RBAC 前后端双重拦截；企业数据隔离生效；密码哈希；写操作全审计；报告/导出/下载做权限校验。
不通过：权限页能显示但后端不拦截；管理员操作不进日志；明文密码。

### 2.5 报告

通过判据：PDF 含 §SRS 3.5 的 15 项；有真实数据表；结论有来源；有版本号；可按当时数据版本重生成。
不通过：报告只有几段 AI 文字、无数据表、无来源、无版本。

## 3. 测试覆盖要求

至少覆盖：功能测试、API 测试、数据导入测试、数据校验测试、权限测试、报告生成测试、算法稳定性测试、SHAP 输出测试、UI 关键流程测试、备份恢复测试、基础安全检查。

每个 P0 闭环项必须有对应自动化或半自动化测试用例，并在交付时给出测试结果。

---

## 4. 禁止伪验收（硬性红线）

以下任一情况即判不通过：
1. 页面能打开但数据写死。
2. 按钮能点但无后端接口。
3. 后端能返回但未持久化。
4. 模型能跑但结果未入库。
5. 报告能生成但无真实数据。
6. 权限页面显示但后端不拦截。
7. 地图是静态图片。
8. 图表是静态假数据。
9. 导入按钮只弹窗不解析文件。
10. 伪造数据/标准/文献/模型性能/甲方字段。
