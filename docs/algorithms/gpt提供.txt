## 2. 规则派生层的标签是给每一个指标都打标签吗？这一层主要干什么？

这里要重新说清楚。

**不是给所有指标都强行打一个标签。**
更准确地说：

> 对每一个“有适用标准/阈值/区间要求”的指标，在指定用途轨道下计算一个规则障碍值。

例如：

```text
Cd 在生产轨：
根据 GB15618 + pH 分段阈值计算超标倍数或 severity。

pH 在生产轨：
根据生产用地适宜区间计算偏离程度。

pH 在生态轨：
根据绿化种植土壤或生态恢复要求计算偏离程度。

SOC / CEC：
如果有标准、文献阈值或项目因子库阈值，则计算功能限制程度。
如果没有可靠阈值，只作为候选解释因子或建议补测项。
```

所以规则派生层主要做三件事：

### 第一，给系统一个“不会乱讲”的底线

规则层告诉用户：

> 按照当前标准和阈值，哪些指标已经构成明确限制。

这比 ML 更稳定，也更容易向甲方解释。zzv0.4 里也写了“标签 = GB15618/GB36600 阈值规则派生”，且强调这一层是规则引擎，不是黑箱模型。

### 第二，给 ML 一个训练目标或校准锚点

如果完全没有规则层，模型不知道什么叫“障碍”。
但这里有一个风险：如果目标完全由 `C_i / threshold_i` 派生，而输入又包含 `C_i`，模型很可能只是学习规则公式。

这不是一定错，但它的表述必须改成：

> 本模型学习的是规则障碍评分在不同场地条件下的归因模式，而不是发现一个完全独立于标准的新真理。

### 第三，给用户上传数据时做即时诊断

用户上传一个新场地后，规则层可以马上给出：

```text
哪些指标有明确超限；
哪些指标缺少标准；
哪些指标未检测；
哪些指标需要补测；
哪些指标只能作为参考。
```

这个比单纯 ML 更可靠。

## 3. 现有逻辑下 ML 如何判定哪些是障碍，哪些是关键障碍？凭什么说 SHAP 值是障碍高度？

这个地方是 zzv0.4 最大的语言风险。

### 不能直接说“SHAP 值就是障碍高度”

SHAP 是模型解释值。它解释的是：

> 在当前模型、当前目标变量、当前输入特征条件下，某个因子对模型输出的贡献。

所以只有在你先定义清楚：

```text
模型输出 = 生产功能障碍指数
或
模型输出 = 生态功能障碍指数
```

时，SHAP 才能解释为：

```text
该因子对生产/生态障碍评分的贡献度
```

而不能直接说：

```text
SHAP = 真实障碍高度
```

更严谨的命名应该是：

```text
模型贡献度
障碍贡献度
障碍解释值
对障碍评分的贡献
```

不要叫“障碍高度”这么绝对。

### 推荐的判定逻辑

我建议把结果分成三层，而不是让 ML 一锤定音。

#### 第一层：明确障碍因子

来自规则层：

```text
该因子有检测值；
该因子有适用阈值；
检测值超过阈值，或偏离适宜区间；
则判定为明确障碍。
```

例如 Cd 超生产轨阈值，pH 偏离生产适宜区间，都可以是明确障碍。

#### 第二层：关键障碍因子

关键障碍不是“只要超标就是关键”，而是满足下面条件之一：

```text
1. 规则 severity 高；
2. 在该用途轨道中权重高；
3. 在模型解释中贡献度高；
4. 在多个采样点或多个版本中稳定出现；
5. 专家/标准认为其对目标用途具有强限制。
```

可以给一个工程化公式：

```text
关键障碍得分 =
0.45 × 规则严重度
+ 0.25 × 用途权重
+ 0.20 × 模型贡献度
+ 0.10 × 数据覆盖/证据等级
```

然后按得分排序。

#### 第三层：潜在障碍 / 建议补测

如果文献认为重要，但用户没有检测，比如 SOC、CEC、酶活性、微生物多样性，就不要硬排进 Top-N。
应该显示为：

```text
未检测但建议补测的功能限制因子
```

这比强行让模型插补后输出更可信。

## 4. 有些生产/生态主导指标数据里没有，怎么说服甲方？文献报道不一致，凭什么文献一定对？

你这个质疑非常对。

**文献不是圣旨，文献只能作为候选因子和权重依据，不能替代场地实测。**

最稳的解释口径是：

> 系统不是因为某篇文献说某因子重要，就直接判它是本场地障碍；系统会先看用户是否检测了该因子，再看是否有适用标准或阈值，最后才结合文献证据判断它是否应进入补测建议或辅助解释。

也就是说，要建立**证据等级**。

### 建议分四级

```text
A级：本场地实测 + 国家/行业标准阈值
可以直接进入核心诊断。

B级：本场地实测 + 因子库/地方标准/工程规范阈值
可以进入核心诊断，但标注依据来源。

C级：有文献支持，但本场地未检测
不能进入 Top-N，只能作为建议补测项。

D级：只有弱文献或代理变量
只能作为背景说明，不用于正式排名。
```

这非常重要。你们的统一障碍因子知识库目前有 403 条记录、122 个唯一因子，其中生产用地 183 条、生态用地 220 条，说明因子体系可以覆盖生产和生态两类用途，但这只是知识库覆盖，不等于每个用户上传场地都检测齐全。

之前推进计划也明确提醒过：生态功能指标最容易稀疏，不能把缺失指标强行插补为真实生态功能；生物活性指标重要但数据不足，应作为局限和后续补数重点。

所以给甲方的解释应该是：

```text
本系统只对已检测且有依据的指标输出正式障碍诊断；
对未检测但与用途高度相关的指标，系统输出补测建议；
系统不会把未检测指标伪装成已诊断结论。
```

这句话很关键。

## 5. 如何保证生产轨和生态轨得到不同障碍因子？

先说底线：**不能承诺一定不同。**

如果一个场地 Cd、As、Pb 极严重超标，那么生产轨和生态轨都把 Cd/As/Pb 排在前面是合理的。硬要它们不同，反而显得假。

你能保证的是：

> 两条轨道的评价目标、阈值库、指标权重、候选因子集合和解释文案是分开的。

这样当数据中存在 pH、CEC、SOC、坡度、容重、入渗率、含盐量、有机质等功能性指标时，两条轨道自然会分开。

### 生产轨为什么会不同？

生产轨关注的是：

```text
能不能安全生产；
作物能不能吸收污染物；
根系能不能生长；
肥力是否足够；
水盐条件是否适合。
```

所以生产轨里 Cd、As、Pb、pH、CEC、SOC、有效磷、速效钾、土壤容重、有效土层、坡度等更重要。推进计划里也把生产功能障碍拆成污染限制、根系生长限制、肥力限制、水盐限制、地形/土层限制等。

### 生态轨为什么会不同？

生态轨关注的是：

```text
能不能恢复植被；
能不能维持微生物和土壤生物活性；
能不能形成稳定土壤结构；
能不能支持雨洪调蓄、固碳、生境功能。
```

所以生态轨里生物可利用性、结构水文、孔隙度、入渗率、压实、发芽指数、微生物、酶活性、SOC、植被恢复潜力等更重要。推进计划里也明确列出了生态功能障碍的这些模块，并强调低覆盖生态指标不能强插补。

### 给甲方的“完美解释”

可以这样说：

```text
同一份检测数据进入系统后，生产用途和生态用途不是换个标题重新算一遍，而是进入两套不同的用途规则。

生产用途优先回答：
这块地能不能安全、稳定、持续地用于生产？

生态用途优先回答：
这块地能不能恢复植被、生境、土壤结构和生态功能？

因此，同一个污染物如果极严重，两条路径都会提示；
但对于 pH、CEC、有机质、坡度、容重、入渗率、生物活性等功能性指标，两条路径的权重和解释会不同。
如果用户没有检测这些指标，系统不会编造差异，而会提示“当前数据不足以评价该类功能限制，建议补测”。
```

这个说法比“我们保证两边排名不同”更专业。
