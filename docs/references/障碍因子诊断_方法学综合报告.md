## 一、6 个场景的差异化障碍因子矩阵

> **设计原则（来自裴总双轨报告第17、19、209-245行）**：同一块地、同一批检测值，两条轨道输出**不同**排序才是正常的；"两轨输出完全一样"应列为红旗。污染总量 ≠ 有效暴露/有效危害，这是生态轨设计的理论地基 [#26, #27, #28]。

| 场地×轨道 | 主导障碍因子（应有，含文献依据） | 标签设计重点 | 特征工程重点 |
|---|---|---|---|
| **HM × 生产** | 残留食安类（Cd/As/Pb，因 GB15618 食用安全阈值低）→ **作物可吸收态**重于总量 [#66 GB15618, #26, #28] | `food_safety_severity`（权重~0.45）+ 作物吸收风险（~0.25）；标签由 GB15618 pH 四段路由阈值派生 | pH(影响有效态+阈值段)、CEC、有效态金属、SOM、作物敏感性、灌溉/耕作历史；pH×金属交互项 |
| **HM × 生态** | 生物可利用性 + 生态毒性主导：**总量高但不活跃** vs **总量一般但高可利用**的区分 [#26 Semple2004, #27 NRC2003, #28 Traina1999, #29-31 土壤健康] | `bioavailable_toxicity`（~0.35）+ 微生物/植被恢复惩罚；GB36600 二类用地宽阈值 [#67] | 有效态/孔隙水代理、SOM、微生物/酶活性、团聚体、植被建立指标；生态毒性代理 |
| **OP × 生产** | 食用路径残留（PAH/农药进入食物链）+ 挥发/降解相关因子 [#45 ES+LCA, #46] | `edible_pathway_severity` + 挥发/降解代理；GB36600 一类严阈值 [#67] | PAH总量/单体、农药残留、挥发代理、作物类型、残留半衰期相关理化 |
| **OP × 生态** | 生物可利用性 + 植被/微生物响应主导（PAH/PCB/农药的生态毒性，非食用路径）[#45, #52, #53] | `bioavailability_proxy` + 植被/微生物响应（~0.25+0.20）；生态二类宽阈值 | PAH生物可利用代理、植被响应、微生物群落/酶活性、降解微环境因子 |
| **HM+OP 复合 × 生产** | 重金属与有机污染物的**协同/拮抗交互**：如有机质改变金属有效态，或农药影响金属迁移 [#44 AHP-TOPSIS, #46, #47] | 组合 severity，交互项需显式建模（不能纯相加） | 重金属+有机浓度 + pH/SOM 交互项 + 复合暴露指标；PI_Nemerow 类综合指数 |
| **HM+OP 复合 × 生态** | 复合毒性 + 微生物/植被多重胁迫；生态功能恢复优先级 [#48 多功能, #52, #53 微生物] | 复合 `bioavailable_toxicity` + 功能恢复惩罚 | 有效态复合、微生物多功能性指标、团聚体恢复、植被建立 |

**依据要点（文献级）**：

- 重金属"总量"与"有效暴露"不等价是生态轨独立设计的核心理论：[#28 Traina & Laperche 1999] 明确"总浓度与有效暴露不同"，[#27 NRC 2003] 是 contaminant bioavailability 权威综述，[#26 Semple 2004] 指出生物可利用性定义本身复杂——这支撑"HM×生态"必须用有效态/毒性代理而非总量 [#26,#27,#28]。
- 生产轨以作物安全为纲：[#66 GB15618] 是农用地风险筛选/管控国标（食安基线），[#70 GB/T33469 耕地质量等级] 给生产轨产能/农艺指标 [#66,#70]。
- 生态轨以土壤健康/功能恢复为纲：[#29-33]（Doran 1994、Bünemann 2018、Lehmann 2020、SMAF 2004 等）建立土壤质量/健康评价框架，[#34-38] 关联生态系统服务与土壤功能，[#39/#40 FAO 土地评价] 提供"不同用地目标→不同限制因子"框架，[#41 MCDA/GIS] 给空间决策支撑 [#29,#30,#31,#33,#34,#36,#39,#40,#41]。
- 复合场地的交互：[#44] AHP-TOPSIS-模糊用于植物筛选（复合胁迫排序），[#46] ML 识别潜在污染点可解释性，[#47] 重金属空间风险 ML——这些是复合场景因子交互建模的先例 [#44,#46,#47]。
- 修复方向派生：[#44,#45,#50,#51] 提供修复技术选型/可持续评估方法，供"反事实→修复建议"链路引用 [#44,#45,#50,#51]。

## 二、标签体系重建方案：从二分类 → 多标签 + 排序（含 prod/eco 差异化）

### 2.1 当前实现的问题（对照文件:行号）

- `ml/etl/build_training_splits.py:175-204` `_label_dual()`：标签 = **"任一因子超对应轨阈值 → 1"** 的二分类（木桶效应）。丢失了**哪些**因子是障碍、障碍多高、严重度梯度。
- `ml/etl/build_training_splits.py:200-203`：有机物 OP 双轨**暂同用一类阈值**（`lab_prod=lab_eco`），生态二类对齐被标注"待 Wave B"未实现 → 生态轨标签没有真正差异化。
- `ml/etl/build_training_splits.py:49-51`：HM 块默认 pH 段 + 默认用地类型；生态轨默认"二类用地"是项目组定义，缺真实生态响应标签。
- `backend/.../diagnosis_service.py:422-457` `_single()`：诊断只取 `predict_proba[:,1]` + SHAP global |mean_abs|，severity 来自事后规则（`pollutant_exceedance_factors` `severity=(max_exceed-1)*0.8+affected_fraction*0.2`，见 `diagnosis_service.py:288`），**标签本身不含严重度信息**。

### 2.2 文献要求（裴总报告第84-91、217-243行 + 文献）

- 不应压成单标签二分类，应做**多标签障碍识别 + 因子排序**（裴总报告第84行）。
- severity 公式（裴总报告第86-89行）：
  ```python
  severity = max(0, log2((value_used_for_model + eps) / (threshold + eps)))
  weighted_severity = severity * factor_weight
  ```
- prod/eco 标签公式应直接把差异写进权重（裴总报告第217-233行）：
  ```python
  prod_score = 0.45*food_safety_severity + 0.25*crop_uptake_risk
             + 0.20*soil_fertility_constraint + 0.10*management_feasibility_penalty
  eco_score  = 0.35*bioavailable_toxicity + 0.25*vegetation_establishment_penalty
             + 0.20*microbial_function_penalty + 0.20*soil_structure_recovery_penalty
  ```
- 因子-轨道二维标签（裴总报告第237-243行）：`y_prod_cd = f(total_cd, pH, crop_type, threshold_GB15618, available_cd)`；`y_eco_cd = g(available_cd, porewater_proxy, pH, SOM, eco_toxicity_proxy)`。
- 权重确定方法：[#42 AHP] 主观权重 + 一致性检验；[#43 模糊集] 模糊综合评价；[#54 Entropy-AHP-WASPAS] 客观+主观组合赋权；[#44] AHP-TOPSIS-模糊用于修复植物筛选——这些给权重/排序的方法学背书 [#42,#43,#44,#54]。
- **标签治理前置**：[#6 Northcutt confident learning] 要求对规则派生/专家修正标签做错标审计；[#9 模型卡]/[#10 数据卡] 要求把标签定义/阈值版本写入文档 [#6,#9,#10]。

### 2.3 重建方案（可落地）

1. **因子级多标签**：每个 analyte 生成 `{factor, track}` 二维标签矩阵（替代单一 `标签_生产/标签_生态`）。`_label_dual` 应输出每因子的 `severity` 而非仅 0/1。
2. **severity 派生**（在 `build_training_splits.py` `_label_dual` 内）：每因子 `severity_i = max(0, log2((val_i+eps)/(thr_i+eps)))`，`weighted = severity_i * weight_i(track, factor, land_use)`。
3. **prod/eco 权重表**：新建 `factor_rule` 表（裴总报告第53-65行 SQL），含 `track/threshold_type/threshold_value/weight/standard_code/standard_version/applicable_land_use`，权重来源标注 [#42/#54]。
4. **排序学习输入**：因子 severity 向量 → learning-to-rank（如 LambdaMART/LightGBM ranker）或 SHAP 排序回归目标。这样"哪个因子是 top-1"成为模型直接学习的目标，而非事后 SHAP 解释。
5. **OP 双轨真正差异化**：落实"待 Wave B"——生态轨 OP 用二类宽阈值 + 生物可利用代理，而非与生产轨同值（`build_training_splits.py:203` 的 `lab_eco=lab_prod` 需拆分）。
6. **标签审计 stage**：每轮训练前用 confident learning [#6] 排查疑似错标，输出候选复核清单。

## 三、验证协议升级方案：嵌套CV + 多种group切分 + 因子排序指标

### 3.1 当前实现的问题

- `ml/models/rf_barrier.py:62-63` `train()`：用 `train_test_split(..., stratify=y)` **随机切分**——这是会话档案中被反复指出的乐观偏差来源（裴总报告2第5-7行）。
- `ml/models/dataset_splits.py:117-138` `build_real_splits()`：按 DOI/Source 连通分量做 group split（train/valid/test/external）——**这是对的**（零跨集泄漏），但只是**单一**切分，没有 CV 层，也没有 region/time/source 的多套切分。
- autoresearch EXPERIMENTS.md 已实证：旧口径 StratifiedKFold 随机切分 CV=0.83 是虚高（同文献跨折泄漏 +0.17）；0泄漏 GroupKFold 物理上限 test~0.68-0.70。
- 阈值固定 0.5：`rf_barrier.py` 无 fold 内阈值调优（`predict()` 用默认）。
- 预处理未进 Pipeline：`build_clean_conc_features.py` 在切分**前**全量算缺失标记/工程特征。

### 3.2 文献要求

- [#1 Cawley & Talbot 2010]：模型选择与评估共用同一数据 → 选择偏差 → 必须**嵌套** CV（内层选模型/调参，外层估泛化误差）[#1]。
- [#55 GroupKFold] + [#56 Common Pitfalls]：分组 CV 防同组跨折泄漏；**所有预处理进 Pipeline**，fold 内拟合 [#55,#56]。
- [#57 Calibration]：概率输出需校准，校准方式写入注册表；阈值不应在训练同数据上调 [#57]。
- 裴总报告1第126行 + 报告2第39行：至少配置 `LeaveOneSiteOut / LeaveOneRegionOut / time-based split / source split` 四套验证。
- 裴总报告1第141行：实验矩阵覆盖站点外推、区域外推、时间外推、来源外推、压力测试（缺失/噪声/极端/合成扰动注入）；synthetic/demo 只用于压力测试，禁入正式效果报告。
- [#64 scipy.bootstrap]：top-k/rank/calibration 带 95% CI；[#65 scipy.permutation_test]：两模型/两轨差异非参显著性检验 [#64,#65]。

### 3.3 升级方案（可落地）

1. **嵌套 CV 架构**：
   - 外层：`GroupKFold(n_splits=5, groups=DOI/Source连通分量)` 估泛化误差（替代 `train_test_split` 随机切分，`rf_barrier.py:62`）。
   - 内层：`GroupKFold` 调超参（[#5 Probst] 只调 `max_features/min_samples_leaf`，`n_estimators` 设收敛值）。
2. **四套 group 切分并列报告**（每组各跑一轮外层 CV，指标取分布）：
   - `LeaveOneSiteOut`（group=site_id）
   - `LeaveOneRegionOut`（group=province/region_code）
   - `time-based split`（按 `collected_at` 排序）
   - `source split`（group=data_origin/DOI/Source）
3. **预处理全进 Pipeline**：`SimpleImputer/StandardScaler/feature_selection/工程特征` 全部包进 `sklearn.Pipeline`，fold 内 fit（[#56] 红线）。`build_clean_conc_features.py` 的全量清洗需拆为"清洗（可全量，不涉标签）" vs "填充/缩放/筛选（必须 fold 内）"。
4. **阈值 fold 内选**：用内层 valid 集 PR 曲线 F_β 最优点选阈值，外层只评估（[#57]）。
5. **因子排序指标体系**（裴总报告1第139行，这才是核心交付指标）：

   | 指标 | 用途 | 文献/来源 |
   |---|---|---|
   | top-k precision / recall | 障碍因子是否被正确识别进 top-k | 裴总报告1第139行 |
   | rank correlation (Kendall/Spearman) | 排序稳定性 | [#64] |
   | SHAP consistency（跨折排序稳定性） | 解释可复现性 | [#3],[#60] |
   | coverage / calibration | 概率可信度 | [#57],[#8] |
   | OOD score / 人工复核触发率 | 部署安全 | [#59],[#8] |
   | AUC / F1 / PR-AUC / Brier / log loss | **仅作模型健康指标**，非核心 | [#57] |

6. **统计检验**：所有指标用 [#64 bootstrap] 报 95% CI；两轨/两模型差异用 [#65 permutation_test] [#64,#65]。

## 四、可解释性三层落地方案

> **总原则（裴总报告2第47-49行 + [#2 Rudin2019]）**：标签若规则派生，**第一解释层永远是规则层**，不是 SHAP。高风险场景优先内生可解释模型，不靠事后解释黑箱 [#2]。

### 4.1 第一层：规则层解释（全局结构）

- 先告诉用户："该障碍由哪些监管阈值、pH 分段、污染因子判定"，再说明统计模型在信息不完整时做风险近似（裴总报告2第49行）。
- 来源：规则库（GB15618 [#66] / GB36600 [#67] / HJ25.5 [#68] / HJ/T166 [#69] / GB/T33469 [#70]）+ `factor_rule` 阈值/权重表。
- 当前已有雏形：`diagnosis_service.py` 的 `pollutant_exceedance_factors`（`source="threshold_exceedance_rule"`）和 `production_limiting_factors`（`source="production_threshold_rule"`）——但当前是**与 SHAP 混排**（`diagnosis_service.py:445-453` `all_ranked` 合并去重），应**分层呈现**而非混在同一列表。
- 配套：模型卡 [#9] + 数据卡 [#10]（训练数据/性能切片/缺失分布/局限/使用边界）[#9,#10]。

### 4.2 第二层：全局变量作用解释（SHAP + permutation + ALE 组合）

- **主**：SHAP（[#3 Lundberg & Lee 2017] 树模型成熟、可加总、形成障碍因子贡献表）[#3,#60]。
- **辅1：permutation importance**（[#58]）——单一 SHAP 排序在相关特征下易误导，需对照（裴总报告2第51行）[#58]。
- **辅2：ALE**（[#4 Apley & Zhu 2020]）——土壤协变量强相关，**PDP 会因离开数据流形外推失真，ALE 更稳健**（裴总报告2第53行）[#4]；[#25 ICE] 看个体异质性 [#25]。
- 当前缺口：`ml/explain/shap_service.py` 只有 SHAP，无 permutation、无 ALE（裴总 reform_plan 已列）。
- 落地：新建 `explain/ale_export.py`、在 SHAP 旁并排 permutation importance；相关特征对（pH-金属、SOM-金属）用 ALE 而非 PDP。

### 4.3 第三层：局部个体解释 + 反事实→修复建议

- **局部解释**：单场地的关键因子 + 阈值边界 + 相似案例 + 不确定性区间（conformal [#8]）[#8]。
- **反事实**（[#24 Wachter 2017]）："如果想让某因子不再进入 top-3，应改变什么"→ 直接转成**修复行动建议**（裴总报告1第145行）[#24]。
  - 反事实锚定修复技术库：[#44 AHP-TOPSIS 植物筛选]、[#45 ES+LCA 棕地]、[#50 可持续修复]、[#51 纳米修复农地]——把"降低因子 X 的 SHAP 贡献"映射到"采用技术 T" [#44,#45,#50,#51]。
- LIME（[#22]）作单样本轻量对照；IG（[#23]）仅在引入深度模型时启用 [#22,#23]。
