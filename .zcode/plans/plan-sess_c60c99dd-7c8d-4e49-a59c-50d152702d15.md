# SRS Round10 报告格式 & 文件管理系统 全面修复方案

## 问题诊断摘要

经过全面排查，发现以下核心缺陷：

### 报告系统（3个问题）
| # | 问题 | 根因 | 影响 |
|---|------|------|------|
| R1 | DOCX 报告格式简陋 | `render_docx()` 只用 python-docx 基础表格，无红头文件格式、无页眉页脚、无专业排版 | 甲方拿到的 Word 报告像草稿 |
| R2 | 所有报告都是"追溯"类型 | `generate()` 固定调用 `collect()` 生成全量报告，不区分来源页面 | SSUI页面生成的报告和追溯页面一样 |
| R3 | 分析页无预览 | SSUI/Obstacle/Reconstruction 页直接下载，不提供预览 | 用户无法在浏览器里先看再下载 |

### 文件管理系统（5个问题）
| # | 问题 | 根因 | 影响 |
|---|------|------|------|
| F1 | 无独立文件管理页面 | 所有文件只能通过五阶段工作流上传，无全局文件库 | 管理员无法跨场地管理文件 |
| F2 | 上传不能选文件类型 | `FileObject` 模型无 `category` 字段，前端 `FILE_ROLES` 仅限阶段角色 | 无法区分污染数据/施工方案/审批方案 |
| F3 | 上传不能指定单位/时间 | `organization_id` 字段存在但前端从未暴露上传组织选择 | 无法追溯文件来源单位 |
| F4 | 非PDF文件不能预览 | 仅 TraceDetail 有 PDF iframe 预览 | 图片/DOCX 用户只能下载 |
| F5 | 下载权限覆盖不全 | `file:download` 权限仅检查但部分页面未提供下载按钮 | 管理员看不到下载入口 |

## 实施方案

### 阶段一：报告格式重做（~2h）

#### 1.1 重写 DOCX 生成器 `report_service.py::render_docx()`
- **红头文件封面**：添加红色双线标题头、公文编号、密级标注位
- **页眉页脚**：页眉"污染场地土壤生态-生产功能重构监管系统"，页脚页码
- **专业排版**：
  - 正文 SimSun 12pt，标题 SimHei 加粗
  - 表格交替行底色 (#F5F7FA / #FFFFFF)，表头深蓝底白字
  - 段落 1.5 倍行距，首行缩进 2 字符
  - 添加"SRS监管系统"半透明水印
- **图件嵌入**：现有 `_embed_docx_image` 保留，优化尺寸为页宽 90%

#### 1.2 增强 HTML 模板 `traceability_report.html`
- 添加封面页（含报告编号、密级、生成日期）
- 表格添加斑马纹和圆角边框（与 PDF 渲染兼容）
- 图标卡（4-up dashboard）增强配色

#### 1.3 报告类型区分
- `report_service.py` `generate()` 新增 `report_scope` 参数：
  - `"full"` → 当前行为（全量15项）
  - `"ssui"` → SSUI专用章节（D1-D25指标清单、B1/B2分项、时间衰减曲线）
  - `"diagnosis"` → 诊断专用章节（Top-N障碍因子、KOS五分量、SHAP贡献图）
  - `"reconstruction"` → 重构专用章节（生产/生态分项评价、限制因子矩阵）
- 各分析页面传递对应 `report_scope`
- 文件命名：`SSUI评价报告_场地X_v1.pdf` / `诊断报告_场地X_v1.pdf` 等

### 阶段二：文件管理中心（~3h）

#### 2.1 数据库：FileObject 模型扩展
```python
# backend/app/models/__init__.py
class FileObject(Base, TimestampMixin):
    # ... 现有字段保留 ...
    category: Mapped[str | None] = mapped_column(String(40), nullable=True)  
    # 枚举: pollution_data/construction_plan/approval_doc/survey_report/effect_report/maintenance_plan/other
    description: Mapped[str | None] = mapped_column(Text, nullable=True)
```

文件分类枚举：
```python
FILE_CATEGORIES = {
    "pollution_data": "污染点位数据",
    "construction_plan": "施工方案", 
    "approval_doc": "审批方案",
    "survey_report": "场地调查报告",
    "effect_report": "效果评估报告",
    "maintenance_plan": "管护方案",
    "monitoring_data": "监测数据",
    "other": "其他材料",
}
```

#### 2.2 后端：新建独立文件管理 API
新建 `backend/app/api/files.py`（或扩展现有 workflow.py）：
| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| `GET` | `/files` | `file:read` | 列出所有文件(支持?site_id=&category=&org_id=过滤) |
| `GET` | `/files/{id}/preview` | `file:read` | 返回文件流(Content-Disposition: inline)用于预览 |
| `GET` | `/files/{id}/download` | `file:download` | 返回文件流(Content-Disposition: attachment)下载 |
| `POST` | `/files/upload` | `data:input` | 上传文件(form: file, category, description, site_id?) |
| `PUT` | `/files/{id}` | `data:input` | 更新文件元数据(category, description) |
| `DELETE` | `/files/{id}` | `data:input` | 删除文件及物理存储 |

#### 2.3 前端：新建文件管理中心页面
**新文件**: `frontend/src/pages/FileManagement.tsx`

功能布局：
- **顶部筛选栏**：场地下拉框 + 文件类型下拉框 + 日期范围选择器 + 搜索框
- **文件表格**（antd Table）：
  - 列：序号 | 文件名(可点击预览) | 类型Tag | 所属场地 | 大小 | 上传单位 | 上传者 | 上传时间 | 操作
  - 分页：默认 15 条/页
  - 排序：按上传时间倒序
- **上传弹窗**（Modal + Upload）：
  - 选择场地（Select）
  - 选择文件类型（Select with FILE_CATEGORIES）
  - 描述文本框（TextArea）
  - 拖拽/点击上传区（Upload.Dragger）
- **预览弹窗**（Modal）：
  - PDF → `<iframe>` 内嵌
  - 图片(png/jpg/gif/webp) → `<img>` 标签
  - 其他类型 → "此文件类型不支持在线预览，请下载后查看"
- **操作按钮**：预览(EyeOutlined) | 下载(DownloadOutlined) | 编辑(EditOutlined) | 删除(DeleteOutlined + Popconfirm)

#### 2.4 导航集成
- `App.tsx` ALL_NAV 新增：
  ```tsx
  { key: "/files", icon: <FolderOutlined />, label: "文件管理", perm: "file:read" },
  ```
- `main.tsx` 路由新增：
  ```tsx
  <Route path="files" element={<RequirePermission code="file:read"><FileManagement /></RequirePermission>} />
  ```
- `api/client.ts` 新增文件管理 API 方法

### 阶段三：报告生成优化（~1h）

#### 3.1 报告按钮重构为共享组件
新建 `frontend/src/components/ReportActions.tsx`：
- Props: `siteId`, `reportScope` ("ssui"|"diagnosis"|"reconstruction"|"full")
- 提供"预览PDF"和"下载PDF/DOCX"两个按钮
- 预览复用 TraceDetail 现有的 iframe Modal 模式

#### 3.2 各分析页接入共享组件
- `SSUIAnalysis.tsx` → `<ReportActions siteId={sid} reportScope="ssui" />`
- `ObstacleAnalysis.tsx` → `<ReportActions siteId={sid} reportScope="diagnosis" />`
- `ReconstructionAnalysis.tsx` → `<ReportActions siteId={sid} reportScope="reconstruction" />`
- 删除各页面内的重复 genReport 代码

#### 3.3 后端支持 report_scope
- `workflow.py` 的 `generate_report` 端点新增 `scope` 查询参数
- `report_service.py::generate()` 根据 scope 调用不同的章节构建函数
- `report_service.py::collect()` 拆分为 `_collect_full()` / `_collect_ssui()` / `_collect_diagnosis()` / `_collect_reconstruction()`

---

### 阶段四：文件预览增强（~0.5h）

#### 4.1 TraceDetail 增强
- 附件列表中的文件名点击 → 判断文件类型：
  - 图片 → Modal 内 `<img>` 展示
  - PDF → 保持现有 iframe 行为
  - DOCX → 提示"请下载后查看"（浏览器不支持直接预览）

#### 4.2 已有文件管理页的预览
- 文件管理页的预览弹窗：支持 PDF（iframe）、图片（img）、其他（提示下载）

## 执行顺序

1. **数据库模型** → 添加 category/description 字段到 FileObject
2. **后端 API** → 新建 files.py，修改 workflow.py 和 report_service.py
3. **报告格式** → 重写 DOCX 生成器，增强 HTML 模板
4. **前端组件** → 新建 FileManagement、ReportActions
5. **前端集成** → 修改各页面接入新组件，更新路由和导航
6. **前端构建** → `npm run build` 验证零 TypeScript 错误
7. **全量测试** → `pytest backend/tests/` 验证零失败
8. **Git 提交** → commit + push 到 codex/srs-round10-source-gate

## 风险控制

- **回滚策略**：每阶段完成后独立 commit，方便出问题时 `git revert`
- **兼容性**：FileObject 新增字段均为 `nullable=True`，不影响现有数据
- **现有功能零破坏**：生成的报告保持现有 traceability 类型不变，新增 scope 参数为可选（默认 "full"）
- **前端依赖零新增**：所有新组件使用现有 antd 图标和组件库
